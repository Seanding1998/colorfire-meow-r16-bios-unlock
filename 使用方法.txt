COLORFIRE MEOW R16 Ultra BIOS 隐藏菜单工程 — 使用方法
适用范围：本项目分析的 N16QF1 / AMI BIOS 1.09
============================================================

先看这一条：制作解锁U盘.ps1 不会格式化 U 盘！
------------------------------------------------------------
它不会格式化、不会重新分区，不删除 U 盘其他文件，也不执行 EFI 或写 BIOS。
它只把 USB_一键工具 目录的内容复制到已经准备好的 FAT32 可移动 U 盘。
若 U 盘不是 FAT32，脚本报错退出，不会自行格式化或转换文件系统。

它会更新同名工具文件。更新前，旧文件先备份到：
    U盘:\MEOW\SYNC_BACKUP\时间戳\
已有 MEOW\DATA 和 MEOW\BACKUP 文件保留，不被旧模板覆盖。
目标已有不同的 EFI 启动文件时会拒绝覆盖。
运行前仍应核对盘符，并保留个人重要文件的独立备份。

公开仓库不附带第三方 UEFI Shell 二进制；首次克隆后须自行准备可信、许可允许的
x64 Shell，放到 USB_一键工具\EFI\Boot\bootx64.efi。缺失时制作脚本会明确退出。

一、Windows 中制作或同步 U 盘
------------------------------------------------------------
1. 插入已准备好的 FAT32 U 盘，在“此电脑”确认盘符。以下 E 仅为示例。
2. 在此工程目录打开 PowerShell，执行：

    .\制作解锁U盘.ps1 -DriveLetter E

3. 脚本会复制、备份需覆盖的工具文件，并核对复制后的 SHA256。
4. 复制完成不等于执行解锁；此 Windows 脚本不会改 BIOS 设置。

二、从 U 盘启动
------------------------------------------------------------
重启按 F7，选择 UEFI: LUMIX，进入完整工具菜单。
默认启动只进菜单，不自动开启或关闭 RD MODE。

三、一键开启隐藏菜单
------------------------------------------------------------
在工具菜单按 Q 返回 Shell，在 U 盘根目录执行：
    unlock.nsh

如果当前不在 U 盘根目录，使用当次完整路径，例如：
    fs4:\unlock.nsh

fs4 只是示例，脚本会扫描 fs0..fs31 并定位唯一工具卷。
开启只将当前 Setup[0x8A] 设为1；已为1时不写变量和锁邮箱。
工具写前备份、写后核对完整变量。工具完全退出后手动 reset 重启。
检查普通 BIOS 时不要再从 U 盘启动，正常按 F2。

四、一键还原隐藏菜单开关
------------------------------------------------------------
同样在 UEFI Shell 执行：
    restore.nsh
或：
    fs4:\restore.nsh

还原只将 RD MODE 改为0，其他当前 BIOS 参数保持不变。
它不会恢复出厂设置，不回灌旧完整 Setup，不重置 CBS/PBS 已保存参数。
已为0时不写。还原方向已完成模拟测试，尚未在本机执行写入验证。

五、查看菜单、日志和源码
------------------------------------------------------------
menu.nsh                         完整工具菜单
MEOW\DATA\                       运行日志、表单快照、每次操作前的变量备份
MEOW\BACKUP\                     本机最初解锁前的备份
MEOW\FALLBACK\                   旧版回退程序
源码\build.ps1 -RunTests          在 Windows 编译并运行宿主测试
验证结果\                        构建、测试和同步核验记录
分析数据\、工具分析\             原始研究材料，不能当作当前执行流程
历史归档\                        已停用的旧 SREP 和旧 U 盘方案

六、保持解锁时 Windows 自动更新 BIOS
------------------------------------------------------------
目前的解锁是将一个厂商 Setup 开关设为1，没有刷入修改版 BIOS 主镜像。
因此不能仅凭“隐藏菜单已解锁”就认定官方 Windows 固件更新会损坏机器。
但下一版七彩虹更新包没有经过本项目验证，无法保证 RD MODE、其他配置会如何迁移。

本机当前已确认存在 COLORFIRE System Firmware 1.09 和 EC 1.06 固件设备，
Windows 的驱动包/UEFI Capsule 更新渠道确实适用于这类固件。

若有计划地更新，建议先记录自己改过的参数；在旧的1.09仍运行时，
可以先关闭 RD MODE 并确认读回0，再按官方流程更新。
这属于减少未知条件的保守做法，不是“未还原必然更新失败”的证据；
本工具的关闭方向尚未在本机执行验证，不能只看脚本存在就认为还原成功。

若自动更新已经进入固件刷写界面，应按更新提示保持供电，不要为了还原 RD 而中断刷写。
更新完成后先检查 BIOS 版本和开机状态，菜单可能保留，也可能重新隐藏。

重要：新版 BIOS 尚未验证时，不要直接运行旧版 unlock.nsh 或 restore.nsh，
也不要把旧 Setup 全量备份写回新版。旧工具虽有身份/长度检查，但没有按 BIOS 版本硬绑定，
不能把这些检查当作新版兼容性保证。应重新确认变量布局和锁接口后再用。

若启用了 BitLocker/设备加密，更新前应确认可取得恢复密钥，并按官方更新流程处理；
本工程不修改加密设置。完整依据与边界见同目录“BIOS更新兼容性说明.md”。

当前已解锁的机器日常直接 F2 使用即可，不需要反复运行解锁脚本。
