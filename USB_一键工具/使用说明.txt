MEOW RD MODE 开启与还原工具 0.5
适用：本项目的 COLORFIRE MEOW R16 Ultra / N16QF1 / AMI BIOS 1.09
============================================================

开启隐藏菜单：UEFI Shell 中运行 unlock.nsh
还原菜单开关：UEFI Shell 中运行 restore.nsh
完整工具菜单：运行 menu.nsh（菜单 6 开启，菜单 7 还原）
默认从 U 盘启动进入菜单，不自动开启或关闭设置。

一键还原的范围
------------------------------------------------------------
restore.nsh 只把当前 Setup[0x8A] 的 RD MODE 从 1 改为 0。
其他当前 BIOS 参数保持不变，之前在 CBS/PBS 中保存的参数不会恢复默认。
不刷 BIOS 主镜像，不恢复出厂设置，不整包回灌旧 Setup，不删除启动项。
FAR、SPL、Secure Boot 等设置不在本次还原范围内。

使用步骤
------------------------------------------------------------
1. 从 U 盘启动（F7 -> UEFI: LUMIX），在工具菜单按 Q 返回 Shell。
2. 在 U 盘根目录运行 unlock.nsh 或 restore.nsh。
   不在根目录时可用当次完整路径，如 fs4:\restore.nsh；fs4 不是固定编号。
3. 脚本会自动定位 fs0..fs31 中唯一的工具卷，不需要再选择菜单 6/7。
4. 还原成功时，应看到：

       Readback Setup[0x8A]: 0x0000000000000000
       RD MODE restore verified in NVRAM.

   如果使用了原生写入窗口，还需确认 Re-establish native lock 1 返回 0。
5. 工具完全退出后手动 reset 重启，再进入普通 BIOS 检查。
   下次想重新开启，可再次运行 unlock.nsh。

这些 .nsh 是 UEFI Shell 脚本，不是在 Windows 中双击执行的批处理。
只有主动运行 unlock/restore 或在菜单选择相应操作，才尝试持久写入。
当前值已等于目标值时，不写 Setup，也不调用锁邮箱。

备份与安全边界
------------------------------------------------------------
每次操作都先备份当前完整 Setup，再仅改 RD 字节，保留原属性和其他254字节。
开启备份：MEOW\DATA\MeowSetupBeforeRDNNN.bin
还原备份：MEOW\DATA\MeowSetupBeforeRestoreNNN.bin
日志与快照：MEOW\DATA
最初解锁前的原变量：MEOW\BACKUP\Setup_before_unlock.bin

备份、平台身份、长度、属性或回读不符时拒绝写入或报告失败。
正常写入被保护拒绝时才使用受控窗口；最终强制设回本机默认锁策略1。
原私有锁状态没有读取接口；重锁依据是命令返回成功，不是读取到了原值。
若最终重锁失败，程序退出，应重启后再进行固件操作。

旧程序回退：MEOW\FALLBACK
Windows 工程中的制作脚本只复制并核验U盘文件，不执行EFI、不修改BIOS。

制作 U 盘与 BIOS 更新提示（2026-10-28补充）
------------------------------------------------------------
Windows 制作解锁U盘.ps1 不会格式化或重新分区，只向现有 FAT32 U盘复制文件。
保持 RD MODE=1 不等于刷入改版 BIOS，不能据此断言官方更新必然失败。
七彩虹下一版更新的配置迁移尚未验证，不能保证菜单保留或旧工具兼容。
更新 BIOS 后，不直接运行旧版 unlock/restore，不整包写回旧 Setup。
完整说明见 MEOW\BIOS更新兼容性说明.md；工程根目录另有“使用方法.txt”。
